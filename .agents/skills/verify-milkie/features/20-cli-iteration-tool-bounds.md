# CLI 模型迭代预算与工具数据边界

## 用户入口

SDK `ExecutionClient.start`、`query`、`toolCall`、`reconcile`。沿用 [275 设计](../../../../docs/design/275-cli-iteration-and-tool-bounds.md)，验收为 Issue #275 S1–S3。

## 驾驶路径与判定

| 验收 | 路径 | 可判定结果 |
|---|---|---|
| S1 | Grok/Pi 设置预算 2，耗尽后同上下文设置 50；非法值及 API 传输 | 耗尽失败码明确、停止已确认、原生会话不变；非法约束无模型请求 |
| S1 | Pi 带/不带宿主工具，触发 threshold/overflow 压缩 | 设置预算时取消压缩，不发出绕过计数的压缩请求；正常提供方请求仍在预算外开始前中止 |
| S1 | Pi 提供方内部配置多次重试，首请求返回 429 | 预算执行将内部重试设为零；一次模型迭代仅发出一次底层请求，上层重试继续消耗预算 |
| S2 | 两种 CLI 返回 80 KiB、256 KiB、中文及超限结果 | 合法结果完整交付；超限明确拒绝，效果不重复 |
| S3 | 四类文件输入及核对结果、超过 2 MiB 的编码请求 | 原始字符串与编码边界分开；超限无效果且保存 invalid_input 调用记录 |
| S3 | 经真实 MCP 服务进程提交超过 2 MiB、但仍在帧余量内的请求 | 错误回复与持久拒绝记录均存在，宿主处理函数未执行 |

## 验证方法

`npm run test:execution` 通过 SDK、真实子进程和本地 MCP 服务验证协议及副作用边界；模型来自确定性夹具，不代表供应商登录或远端模型验收。Pi 压缩取消还须使用已安装的 Pi 版本核对原生压缩入口在取消后不会调用压缩提供方。

真实 Grok/Pi 预算耗尽与续接证据按候选版本单列，不能把工具调用次数当作模型 HTTP 请求次数。其它宿主工具及恢复路径分别见功能 18、19。

原生无网络回归：`node tests/e2e/pi-budget-hooks.native.mjs <已安装的Pi包目录>`。当前只接受 Pi 0.85.1，运行真实提供方包装、429 重试与原生自动压缩入口；网络使用内存夹具，远端请求数为零。
